# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A mockup/test bed for a Go web app using Templ, HTMX 4.0 (stable, loaded from jsDelivr in `layouts/base.templ`), Alpine.js 3 (CDN, for small client-side state alongside htmx), Tailwind CSS 4.3 (standalone `tailwindcss` CLI, v4.3.3 installed on the author's Mac) and [shadcn-templ](https://github.com/axadrn/shadcn-templ) pinned to `v2.0.0-beta.15`. HTMX features aren't the point; it's practice for a later project. The module name is `go-templ-mock-1`.

## Commands

All via go-task (`Taskfile.yaml`):

- `task dev` — hot-reload dev server (Tailwind watch + shadcn-templ script bundler watch + `templ generate --watch` with proxy). Sets `SHADCN_TEMPL_DEV=true` so assets are served from disk. Picks the first free port from 8090 (override with `PORT=`/`PROXY_PORT=`).
- `task build` — minified CSS, JS bundle, `templ generate`, `go build -o bin/app .`
- `task run` — build then run `./bin/app`
- `task generate` / `task test` / `task clean`

Single test: `go test ./path/to/pkg -run TestName` (there are currently no project tests; run `task generate` first so `*_templ.go` exist).

Both `templ` and `shadcn-templ` are Go `tool` dependencies in `go.mod`: invoke them as `go tool templ ...` / `go tool shadcn-templ ...`. Add components with `go tool shadcn-templ add <name>`, then `go tool templ generate` and `go mod tidy`.

## Architecture

- `main.go` — plain `net/http` mux. Page routes render templ components via `templ.Handler`; HTMX endpoints (`POST /greet`, `POST /forms/submit`, `GET /feedback/slow`, `GET /analytics/revenue`, `GET /projects/deployments`, `GET /search/results`, `POST /projects/{slug}/promote`) return small templ fragments that replace an `hx-target`. Fragment components live next to their page (e.g. `Greeting`, `FormResult`, `SlowResult`).
- `layouts/base.templ` — document shell (CSS, htmx script, `@components.Scripts()`); `layouts/shell.templ` wraps pages with the nav bar (add new pages to `navLinks` there). `layouts/theme.templ` holds the light/dark/system toggle: an inline head script sets the `dark` class on `<html>` from `localStorage.theme` before paint (note: templ doesn't interpolate inside `<script>`, so it's emitted via `templ.Raw`).
- `pages/` — one `.templ` per page. The `/projects` screens are driven by static mock data in `pages/platform_data.go` (projects, deployments per dev/test/prod, CVEs, errors); there is no database. `/search` searches `pages/search_data.json` (200 generated people, `go:embed`ded and loaded at startup by `pages/search_data.go`).
- `components/` — **vendored shadcn-templ components** (generated by the CLI, one package per component, plus `baseui/` and `floatingui/` JS and `scripts.templ`). Treat as library code: import with e.g. `selectcomp "go-templ-mock-1/components/select"` (`select`/`switch` need aliases), and pass `Props` structs with `ID`, `Class`, `Attributes` pass-throughs. Overlay triggers use helpers like `dialog.Trigger(ctx)` passed as `Attributes`.
- `assets/` — `css/globals.css` is the Tailwind entry (theme tokens); `output.css` and `js/shadcn-templ-*.js` are build outputs (gitignored). Production serves them from the embedded `assets.Assets` FS.

## Gotchas

- Alpine state (`x-data`) must live on an element htmx doesn't swap, or it resets on every swap; see `pages/search.templ` (selection state on the card, only `#search-results` is swapped). `[x-cloak]` is defined in `globals.css`.
- `*_templ.go` files are committed. Regenerating after editing `.templ` files is expected, but don't hand-edit them.
- Don't run `templ fmt` on the whole repo — it rewrites vendored `components/`. Format only `pages/` and `layouts/`.
- The shadcn-templ JS bundle (`assets/js/shadcn-templ-<hash>.js`) is produced by `shadcn-templ bundle` (run by `task build`/`task dev`); don't rebuild it manually or edit minified output. Its filename is referenced from `components/scripts_bundle.go`, which `add`/`bundle` regenerate.
- Components follow Base UI prop names (e.g. accordion uses `Value`/`DefaultValue []string`, not `Open`); check the component's `Props` struct before using one.
